# 用户已确认的长期规则

本文件保存跨项目适用的偏好；项目事实、研究点数量、特定删改意见及章节引用限制放入项目简报。用户当前指示和最新母版优先，更新规则不得把旧项目个例变成永久禁令。

## 交付与协作

- 国网可研使用已确认的国网模板；不套用南网或其他通用格式。
- “直接文字发我”、讨论标题或方案时只给相应聊天内容；“图先不画”时不绘图。
- 采用用户指定的最新母版，另存新版本，保留手工调整。其他人的版本按参考用途吸收，不能按文件名数字高低自动取代母版。
- 已确认标题、方法和格式持续有效；记录明确否定或删除的内容，后续不自动恢复。不重复追问已有答案。
- 多人合稿先参照当前报告已认可的同级课题写法，保留本课题的研究对象和方法。写法规则见[module-writing-rules.md](module-writing-rules.md)。
- 不因任务可能涉及PPT而自动制作PPT，不因讨论可研而自动生成DOCX或PDF。

## 内容

- 研究现状按具体问题展开国内外进展和综合评述，重视相关中文文献，正文通常采用第一作者简称。
- 理论依据采用真实的理论、方法、算法或模型名称，与项目对象和计算链衔接；用原理、假设和边界体现深度。
- 实践依据区分制度需求、外地经验、本地场景和实际工程条件，不把其他项目基础移植为当前事实。
- 研究内容写任务和结果；实施方案写具体方法、过程和验证；难点与拟解决办法逐项对应。
- 项目意义说明新增价值，避免仅罗列工具、部署和示范任务。
- 已认可的“揭示……、构建……、形成……、解决……”和“首先，针对……难题，采用……”保留为可选示例，服从当前模板和上下文。
- 研究点数量、细分层级、篇幅和图片数量不作固定要求；内容完整性优先于页数或公式数。
- 正式报告不写助手解释、自我辩护、核实提醒或过程日志；不编造基础、成果、性能及经济收益。

## Word与公式

- 编辑DOCX加载documents，Word交付自动接入MathType，保留原文件及范围外对象；内容和格式规则以对应参考文件为准。
- 原生MathType、自动编号和零缩进“式中，”要求执行最新依赖；局部文字修改不触发范围外公式重做。
- 保留已有目录、域、编号、书签、批注、修订、图表和分节；明确要求时才更改目录。
- 显式优先PowerShell 7，UTF-8复杂脚本可使用工作区临时`.ps1`；COM兼容和回退执行MathType技能的失败分类。
- 使用独立不可见Word实例，只清理本任务创建的进程。
- 默认不渲染DOCX页面；用户当次明确要求检查最终版式时再渲染。未渲染不判失败，不反复提示。
- 标红、批注分别按本轮要求处理。批注写清改了什么及原因，保留原有批注。
- DOCX交付分别说明Word/MathType COM、包验证和内容提取的实际状态。

## 图和预算

- 图与正文使用同一组已确认标题和方法，保留可编辑源文件；已确认图只做指定修改。
- 图中文字与箭头清晰、对齐，尺寸和源格式服从实际目标，不固定为六张或某一软件。
- 材料费、外委研究和外协测试分类清楚；材料规格写功能，测试写对象、范围、指标和报告；明细与汇总金额一致。
